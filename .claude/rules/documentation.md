# Documentation Rules — room-eye

`docs/` 配下の計画・方針ドキュメントの運用ルール。

## 3 種類の文書の使い分け

書く前に、どの文書に当たるかを必ず判断すること。

| 置き場所 | 役割 | 性質 |
| :--- | :--- | :--- |
| `.claude/rules/` | エージェントが守るべき制約（GPIO 割当・禁止事項・命名規則） | 短く規範的。理由は書かない |
| `docs/` | 計画・設計方針と、そう決めた理由 | 育てる文書。実装しながら更新する |
| `experiment/<name>/EXPERIMENT.md` | 個別実験の記録 | 原則あとから書き換えない（`.claude/rules/experiment-report.md` 参照） |

- 制約そのものは `.claude/rules/` に、その背景・判断理由は `docs/` に書く。同じ内容を両方に重複させない
- `docs/` から `.claude/rules/` を参照するのは可。逆方向の参照は最小限にする

## ディレクトリ構成

```
docs/
├── README.md        索引と運用ルール。文書を追加したら索引も更新する
├── roadmap.md       プロジェクト全体の計画（機能横断）
├── design/          設計方針（機能横断）
├── plans/           機能ごとの実験・開発方針
└── adr/             意思決定記録（Architecture Decision Record）
```

- 機能横断の設計方針は `design/`、機能単位の計画は `plans/` に置く
- 新しい文書を追加したら `docs/README.md` の索引に必ず追記する

## メタ情報（frontmatter）

すべての `docs/` 配下の Markdown は、先頭に以下の frontmatter を置く。

```markdown
---
作成日: 2026-07-27
最終更新: 2026-07-27
ステータス: active
---
```

- 日付は `YYYY-MM-DD` 形式の絶対日付で書く（「先週」「今月」などの相対表現は使わない）
- `ステータス` は `draft`（執筆中）/ `active`（有効）/ `superseded`（別文書に置き換え済み）のいずれか
- **内容を変更したら `最終更新` を必ず更新する**。`作成日` は変更しない
- `superseded` にする場合は、本文冒頭に置き換え先の文書へのリンクを書く

## 生きた文書 と 追記専用文書

| 対象 | 更新方針 |
| :--- | :--- |
| `roadmap.md` / `design/` / `plans/` | **書き換えてよい**。実装して分かったことを随時反映する |
| `adr/` | **追記専用**。既存の ADR は書き換えない |

### ADR（意思決定記録）

- ファイル名は `NNNN-kebab-case-title.md`（4 桁ゼロ埋めの連番）
- 1 ADR = 1 つの意思決定
- 判断を覆すときは、既存ファイルを書き換えず**新しい番号の ADR を追加**し、旧 ADR のステータスを `superseded` に変更して置き換え先へのリンクを追記する
- 構成: `## 背景` / `## 決定` / `## 理由` / `## 結果と影響` / `## 再検討する条件`
- ADR に値するのは、**あとから覆すとコストが大きい判断**（依存ライブラリの採用可否、レイヤ構成、データ形式など）。実装の細部は対象外

## 更新のタイミング

- 実装中に方針と異なる判断をしたら、その場で該当文書を更新する（実装だけ先に進めて文書を放置しない）
- 実験が完了したら、結果を `EXPERIMENT.md` に記録したうえで、`roadmap.md` の現在地と `plans/` の該当箇所を更新する
- 依存ライブラリの採用・不採用を決めたら ADR を追加する

## 注意事項

- 実行していない検証を、実行したかのように書かない（`.claude/rules/cv-research.md` の再現性ルールと合わせる）
- 未確定の値・未検証の前提は `TODO` として明示し、確定したら更新する
- 重い成果物・学習済みモデル・生データを埋め込まない
