# Survey Workflow Rules — room-eye

調査作業（論文・ブログ・実装事例）の記録方法と Issue 連携ルールを定める。

---

## docs ファイルの形式

調査結果は `docs/survey/<カテゴリ>/` 配下にトピック単位で Markdown ファイルを作成する。

### ファイル名

```
docs/survey/<カテゴリ>/<トピック名>.md
例: docs/survey/gesture/mediapipe-hands.md
    docs/survey/edge-inference/yolo-onnx-benchmark.md
```

### ファイル冒頭（必須フロントマター）

```markdown
# <タイトル>

- **関連Issue**: #<番号>
- **調査日**: YYYY-MM-DD
- **カテゴリ**: gesture / detection / edge-inference

## 概要

<3〜5行でこの調査で何がわかったか>
```

### セクション構成

```markdown
## 論文・公式資料

| タイトル | 著者/出所 | 年 | リンク | メモ |
|---|---|---|---|---|

## ブログ・実装事例

| タイトル | 出所 | リンク | メモ |
|---|---|---|---|

## まとめ・所感

<room-eye への応用可能性・採用候補・懸念点>
```

---

## Issue へのコメント形式

調査完了後、対応 Issue に以下の形式でコメントを残す。

```markdown
## 調査完了

docs に記録しました → `docs/survey/<カテゴリ>/<ファイル名>.md`

### 主な発見

- <箇条書きで3〜5点>

### 参考リンク

- [タイトル](URL)
- [タイトル](URL)

### 次のアクション（任意）

- <実験・実装に向けて次にやること>
```

---

## 運用ルール

- 1 つの docs ファイル = 1 つのトピック（広すぎる場合は分割する）
- 調査中に発見した派生トピックは新しいファイルを作り、元ファイルからリンクする
- 未確認・未読の文献は「未読」と明記してリンクだけ記録してもよい
- docs ファイルは Issue クローズ後も残す（将来の実装時の参照資料になる）
