# Experiment Report Rules — room-eye

## 目的

`experiment/` 配下で実験に取り組んだ際は、取り組んだ内容を `EXPERIMENT.md` として残す。
使い方ドキュメント（`README.md`）ではなく、実験の記録として書く。

## 運用単位

- 1 実験ディレクトリ（`experiment/<name>/`）につき `EXPERIMENT.md` は 1 つ
- 基本的に 1 ブランチ = 1 実験目的 を想定する
- スクリプト・設定・（Git 管理外の）出力は、すべて同じ実験ディレクトリ配下にまとめる
- 実験の途中で目的が大きく変わった場合は、新しい実験ディレクトリを切ることを検討する
  （1 つの `EXPERIMENT.md` に無関係な実験を詰め込まない）

## 構成

`EXPERIMENT.md` は以下の 4 セクションで構成する。

1. **目的 (Objective)** — 何を検証・改善したいか、背景（前回の実験や課題からの地続きの問い）
2. **実験条件 (Setup & Hyperparameters)** — 実行環境、モデル・パラメータ・設定ファイル
3. **実験結果 (Results)** — 主要メトリクス、ログ・出力の抜粋
4. **考察とネクストアクション (Discussion & Next Steps)** — 結果の考察、次にやること

実験の性質（実機での動作検証か、GPU 環境でのモデル学習・評価か）によって「環境」やパラメータ表のカテゴリ、
主要メトリクスの中身は変わる。以下のテンプレートはあくまで骨格であり、カテゴリ名・メトリクス名は実験内容に合わせて置き換える。

## テンプレート

新しい実験ディレクトリで `EXPERIMENT.md` を作成する際は、以下をベースにする。

```markdown
# 🧪 [実験の短いタイトル]

## 📌 1. 目的 (Objective)
* [ ] 何を検証・改善したいのか、一言で記述。
* **背景**: 現状の課題や、前回の実験結果からの地続きの問い。

## ⚙️ 2. 実験条件 (Setup & Hyperparameters)
> **環境**: 例) Raspberry Pi 5 / Python 3.11 / ONNX Runtime v1.18
> または） GPU: RTX 4090 / CUDA 12.4 / PyTorch 2.4 / Python 3.11

| カテゴリ | パラメータ名 | 設定値 | 意図・備考 |
| :--- | :--- | :--- | :--- |
| **Data** | `dataset` / `split` | `coco128` / `train:val=8:2` | 小規模データで動作確認 |
| **Model** | `model_path` / `architecture` | `yolov8n.onnx` | 最軽量モデルでFPS重視 |
| **Training** | `epochs` / `lr` / `batch_size` | `50` / `1e-3` / `32` | ベースライン設定 |
| **Control** | `pid_kp` / `ki` / `kd` | `0.1` / `0.01` / `0.0` | 実機制御を伴う場合のみ |
| **Config** | `hydra.config_name` | `base_run.yaml` | 基盤設定を使用 |

> 上記カテゴリは例。実機検証なら Model/Control/Hardware 系、GPU学習なら Data/Model/Training 系など、
> 実験内容に応じて過不足なく選ぶ。

## 📊 3. 実験結果 (Results)
* **主要メトリクス**（実験内容に応じて選ぶ。例）:
  * 実機・リアルタイム系: 推論速度 `15 FPS` (目標: 20 FPS ❌) / サーボの挙動（ハンチング有無）
  * GPU学習・評価系: `val_loss 0.42` / `mAP50 0.81` / 学習時間 `2h30m`
* **ログ/出力（一部抜粋）**:
  ```text
  [INFO] Target detected at (320, 240) - Delta: 0
  [WARN] Motor oscillation detected. Overcompensated by 12 degrees.
  ```

## 💡 4. 考察とネクストアクション (Discussion & Next Steps)
### 🧐 考察 (Why?)
1. **推論速度の不足**: 映像のキャプチャ処理とONNXの推論が同スレッドで動いているため、ボトルネックになっている可能性が高い。
2. **モーターのブレ**: `Kp` が大きすぎるか、微分制御（`Kd`）がないため、行き過ぎた制御を繰り返している。

### 🚀 ネクストアクション (Next)
* [ ] 推論処理をマルチスレッド化（非同期化）してFPSを向上させる。
* [ ] PID制御の `Kd`（微分）を導入し、ブレーキをかけるロジックを追加する。
```

## 注意事項

- 実行できなかった検証・省略した条件は隠さず、結果セクションか考察セクションに理由を明記する
  （`.claude/rules/cv-research.md` の再現性ルールと合わせる）
- パラメータ表に書く値は実際に使った設定ファイル（`config/*.yaml`）や学習スクリプトの引数と一致させる
- 重い成果物・学習済みモデル・生データを `EXPERIMENT.md` に埋め込まない（`data/`・`outputs/`・`models/` は Git 管理外）
- GPU 環境での学習実験の場合、乱数シード・データ分割・学習時間（またはクラウド利用時のインスタンス種別）も記録し、
  ラズパイでの実機検証と同様に再現可能な形で残す
